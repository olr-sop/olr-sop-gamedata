# add-encoding-toolkit: Proposal

## Why

Gamedata text is split between Windows-1251, UTF-8 and pure ASCII, and several files were already damaged by lossy conversions. There was no safe, repeatable way to read, search, convert or repair text: writing UTF-8 into `gamedata/` corrupts Russian strings in game, while the two-pass `ripgrep` workaround is slow and easy to get wrong. Agents also waste tokens re-discovering the same encoding rules.

## What Changes

- Add `tools/encoding/enc.ps1`, one entry point with `scan`, `detect`, `read`, `grep`, `convert` and `restore`.
- Add `tools/encoding/README.md` with the encoding policy, command examples and repair workflow.
- Add a baseline audit generated by `scan` (`tools/encoding/BASELINE.md`) so the damage is measurable.
- Reference the toolkit from `AGENTS.md` and from the OpenSpec project context.
- Fix the policy: `gamedata/shaders/**` is UTF-8 (and should stay UTF-8); all other text under `gamedata/**` is CP1251; repo docs/tools are UTF-8.

## Impact

- New: `tools/encoding/enc.ps1`, `tools/encoding/README.md`, `tools/encoding/BASELINE.md`.
- Updated: `AGENTS.md`, `openspec/config.yaml`.
- No gamedata content is modified by this change; normalization is a separate change.
- Agents can now read and search mixed encodings without corrupting files or wasting two passes.
